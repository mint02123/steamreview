# 02. evidence_level 판단 기준

## 이 문서가 답하는 질문

> Q: 리뷰의 근거가 충분한지 어떻게 판단하는가?
> Q: sufficient와 partial의 차이는 무엇인가?
> Q: weak과 insufficient의 차이는 무엇인가?
> Q: 어떤 표현이 있을 때 evidence_level을 어떻게 매기는가?

## 핵심 원칙 (요약)

근거가 부족한 리뷰는 억지로 대표 리뷰로 만들지 않는다([원칙 4](00_core_principles.md)).
LLM은 입력에 없는 내용을 추측하지 않는다([원칙 5](00_core_principles.md)).

## 1. evidence_level 4단계

`evidence_level`은 다음 4단계 중 하나로 판단한다.

```
sufficient | partial | weak | insufficient
```

| 단계 | 의미 | 핵심 판단 기준 |
|---|---|---|
| sufficient | 근거가 충분함 | 대상·문제·상황·방향이 모두 또는 대부분 명확 |
| partial | 일부 근거 있음 | 대상·문제는 있으나 상황 또는 재현 조건이 부족 |
| weak | 약한 신호 | 카테고리 표현은 있으나 설명이 짧거나 감정 중심 |
| insufficient | 근거 부족 | 대상·상황·요구가 모두 불명확 |

## 2. 단계별 상세 기준

### 2.1 sufficient — 근거가 충분한 리뷰

**조건 (모두 또는 대부분 충족)**
- 대상이 명확하다.
- 문제 또는 요구가 명확하다.
- 발생 상황이나 사용 맥락이 있다.
- 개발자가 확인할 방향이 있다.

**예시 리뷰 (bug)**
> "보스 2페이즈 진입 후 패턴 종료 시 일정 확률로 게임이 멈추고 강제 종료됩니다. RTX 3060, Windows 11 환경에서 5회 중 3회 재현됐습니다."

**예시 설명**
> 문제가 발생하는 기능과 상황이 모두 언급되어 있어 개발자가 확인할 수 있는 근거가 충분하다.

### 2.2 partial — 일부 근거가 있는 리뷰

**조건**
- 대상은 있으나 상황 설명이 부족하다.
- 문제는 있으나 재현 조건이 부족하다.
- 개선 요구는 있으나 구체성이 약하다.

**예시 리뷰 (qol)**
> "인벤토리 정렬할 때 클릭이 너무 많이 필요해서 불편합니다."

**예시 설명**
> 불편한 기능은 언급되어 있으나, 어떤 상황에서 문제가 두드러지는지는 충분히 설명되지 않았다.

### 2.3 weak — 약한 신호만 있는 리뷰

**조건**
- 카테고리 관련 표현은 있으나 설명이 짧다.
- 감정 표현 중심이다.
- 개발자가 바로 조치하기 어렵다.
- 유형별 요약에는 반영할 수 있으나 대표 리뷰로는 약하다.

**예시 리뷰 (balance)**
> "신규 캐릭터 너무 셈"

**예시 설명**
> 밸런스 관련 불만은 감지되나, 어떤 상황·구간에서 강한지 등 구체적인 설명이 부족하다.

### 2.4 insufficient — 근거가 부족한 리뷰

**조건**
- 대상이 없다.
- 상황 설명이 없다.
- 문제 또는 요구가 불명확하다.
- 단순 칭찬, 단순 비난, 농담에 가깝다.
- 개발 피드백으로 보기 어렵다.

**예시 리뷰**
> "별로임 ㅋㅋ"
> "갓겜"
> "이 게임 만든 사람 ㅎㅇ"

**예시 설명**
> 개발자가 확인할 수 있는 구체적인 대상이나 상황이 포함되어 있지 않다.

## 3. 카테고리별 판단 예시

근거 수준은 카테고리에 따라 기대 수준이 다소 다르다. 다음은 참고 예시이다.

### 3.1 bug

| 단계 | 예시 |
|---|---|
| sufficient | "특정 맵에서 NPC와 대화 중 X 키를 누르면 클라이언트가 다운됨, 4회 재현" |
| partial | "가끔 게임이 멈춥니다" |
| weak | "버그 많음" |
| insufficient | "쓰레기 게임" |

### 3.2 balance

| 단계 | 예시 |
|---|---|
| sufficient | "후반 던전에서 직업 A의 광역기 쿨이 너무 짧아 다른 직업이 의미 없어짐" |
| partial | "직업 A가 너무 강합니다" |
| weak | "밸붕임" |
| insufficient | "노잼" |

### 3.3 qol

| 단계 | 예시 |
|---|---|
| sufficient | "전리품 수집 후 인벤토리 정렬에 정렬 버튼 4번을 눌러야 함, 자동 정렬 옵션이 있으면 좋겠음" |
| partial | "인벤토리가 불편합니다" |
| weak | "UI 별로" |
| insufficient | "리메이크 ㄱ" |

### 3.4 feature_request

| 단계 | 예시 |
|---|---|
| sufficient | "협동 미션에서 친구 초대 시 코드 입력만 가능한데, 친구 목록에서 직접 초대 기능이 있으면 좋겠습니다" |
| partial | "친구 초대 기능이 더 편했으면 좋겠어요" |
| weak | "기능 부족" |
| insufficient | "더 잘 만드세요" |

## 4. 점수와 evidence_level의 관계

점수와 evidence_level은 **독립적으로 판단**한다.
- 점수는 모델이 예측한 helpfulness이다.
- evidence_level은 LLM이 리뷰 원문을 보고 판단한 근거 수준이다.

따라서 두 값이 항상 일치하지는 않는다. 충돌 시 처리는 [`03_display_decision`](03_display_decision.md)을 참조한다.

## 5. 판단 시 주의사항

- **추측 금지**: 리뷰에 명시되지 않은 재현 조건이나 환경을 LLM이 만들어내지 않는다([원칙 5](00_core_principles.md)).
- **언어 길이로만 판단하지 않음**: 짧아도 대상·문제가 명확하면 partial 이상일 수 있다. 길어도 감정 중심이면 weak일 수 있다.
- **번역 누락 고려**: 외국어 리뷰의 경우 번역에서 누락된 맥락이 있을 수 있으므로 확실하지 않으면 한 단계 보수적으로 판단한다.
