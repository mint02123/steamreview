# 01. usefulness_score 해석 기준

## 이 문서가 답하는 질문

> Q: usefulness_score는 무엇을 의미하는가?
> Q: 점수가 0.7이면 어떻게 처리해야 하는가?
> Q: 점수가 낮은 리뷰는 무조건 버려야 하는가?
> Q: 점수 경계값(0.79, 0.59 등)은 어떻게 처리하는가?

## 핵심 원칙 (요약)

- **높은 점수**: 핵심 Top-K 후보로 우선 검토 ([원칙 1](00_core_principles.md))
- **중간 점수**: 카테고리 대표 후보로 사용 가능 ([원칙 2](00_core_principles.md))
- **낮은 점수**: QoL·기능 추가 등 약한 신호로 활용 가능, 단 대표 리뷰로는 사용하지 않음 ([원칙 3](00_core_principles.md))

## 1. usefulness_score의 의미

`usefulness_score`는 0~1 범위의 우선순위 점수이다.
이 값은 Steam 리뷰의 `votes_up` 기반 helpfulness를 예측한 결과이다.

해석 시 다음을 명심한다.

- 점수가 높을수록 **우선적으로 확인할 가치**가 높다.
- 점수가 낮다고 해서 **무의미한 리뷰**라는 뜻은 아니다.
- 점수는 **선별 기준**이지, **최종 해석**이 아니다.

`usefulness_score`가 답해주는 질문:
> "어떤 리뷰를 먼저 확인할 것인가?"

`usefulness_score`가 답해주지 못하는 질문(추가 해석 필요):
> "이 리뷰가 개발자에게 왜 유용한가?"
> "이 리뷰는 어떤 유형의 피드백인가?"
> "이 리뷰를 서비스 화면에 어떻게 보여줄 것인가?"

## 2. 점수 구간별 처리 기준

점수 구간은 **고정 정답이 아닌 초기 서비스 설계 기준값**이다.
운영하면서 분포에 따라 조정될 수 있다.

| 점수 구간 | 명칭 | priority | 기본 처리 방향 |
|---|---|---|---|
| 0.80 이상 | 강한 유용 리뷰 | high | 핵심 Top-K 후보 |
| 0.60 이상 ~ 0.80 미만 | 유용 리뷰 | medium | 카테고리 대표 후보 |
| 0.40 이상 ~ 0.60 미만 | 약한 신호 | low | 카테고리 요약에만 반영 |
| 0.40 미만 | 근거 부족 | ignore | 일반적으로 제외 |

### 2.1 0.80 이상 — 강한 유용 리뷰

**조건**
- 리뷰 내용이 비교적 구체적이다.
- 개발자가 확인할 대상이 있다.
- 피드백 유형이 명확하다.
- 서비스 화면에서 대표 리뷰로 보여주기 적합하다.

**기본 처리**
```json
{
  "priority": "high",
  "display_decision": "show_as_core_review"
}
```

### 2.2 0.60 이상 ~ 0.80 미만 — 유용 리뷰

**조건**
- 충분히 유용할 가능성이 있다.
- 전체 Top-K에는 들지 못할 수 있으나, 특정 카테고리를 대표할 수 있다.

**기본 처리**
```json
{
  "priority": "medium",
  "display_decision": "show_if_representative"
}
```

### 2.3 0.40 이상 ~ 0.60 미만 — 약한 신호

**조건**
- 카테고리 신호는 있으나 근거가 충분치 않다.
- 특히 QoL·기능 추가 요청 리뷰가 이 구간에 자주 위치한다.
- 점수가 낮다고 폐기하지 않는다(원칙 3).

**기본 처리**
```json
{
  "priority": "low",
  "display_decision": "use_for_category_summary_only"
}
```

**예시 해석**
> QoL 관련 의견은 존재하지만, 구체적인 상황 설명이 부족하여 핵심 리뷰가 아니라 약한 신호로 처리한다.

### 2.4 0.40 미만 — 근거 부족

**조건 (다음에 해당하면 제외 가능성 높음)**
- 너무 짧은 리뷰
- 단순 감정 표현
- 농담 또는 밈
- 구체적 대상이 없는 비난
- 개발자가 확인할 단서가 없는 리뷰

**기본 처리**
```json
{
  "priority": "ignore",
  "display_decision": "exclude"
}
```

## 3. 경계 케이스 처리 규칙

### 3.1 점수 경계값 (0.80, 0.60, 0.40)

경계값은 **이상(≥) 기준**으로 판단한다.
- 0.80 → 0.80 이상 구간 (high)
- 0.7999 → 0.60 이상 ~ 0.80 미만 구간 (medium)
- 0.60 → 0.60 이상 ~ 0.80 미만 구간 (medium)

### 3.2 점수와 근거 수준이 충돌할 때

점수는 높으나 근거가 약한 경우, 또는 점수는 낮으나 근거가 충분한 경우가 있을 수 있다.

판단 우선순위는 다음과 같다.

- **display_decision은 점수와 evidence_level을 모두 참조한다.**
  세부 매핑은 `03_display_decision`을 참조한다.
- 점수가 0.80 이상이지만 evidence_level이 `insufficient`이면, `show_as_core_review`로 자동 승격하지 않는다.
- 점수가 0.40 미만이지만 evidence_level이 `sufficient`이면, `exclude` 대신 `use_for_category_summary_only`로 격상할 수 있다.

### 3.3 점수가 누락되었거나 비정상값일 때

- 점수가 입력되지 않은 경우: evidence_level과 카테고리 신호만으로 판단하되, `show_as_core_review`는 부여하지 않는다.
- 점수가 0~1 범위를 벗어난 경우: 입력 오류로 보고 priority는 부여하지 않는다.

## 4. 자주 묻는 케이스

### 점수가 0.55인 QoL 리뷰는 버려야 하는가?
아니다. 약한 신호 구간이지만 QoL 카테고리 요약에는 반영할 수 있다(원칙 3).
단 `show_as_core_review`는 부여하지 않는다.

### 점수가 0.85인 단순 칭찬 리뷰는 핵심 리뷰인가?
아니다. 점수가 높아도 evidence_level이 `insufficient`이면 핵심 리뷰가 아니다.
점수와 근거를 함께 본다(3.2 참조).

### 점수가 0.30인 리뷰가 매우 구체적인 버그 재현 절차를 담고 있다면?
드문 케이스이지만, evidence_level이 `sufficient`이면 카테고리 요약 또는 검토 대상에 포함할 수 있다.
다만 이 경우 점수 모델의 신뢰도를 검토할 신호로도 기록할 가치가 있다.
